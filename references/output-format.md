## 格式规范

### 整体输出结构

### 发送方式（2026-09-29 用户明确要求）

**发给用户时，整份文档必须包在 ```` ```markdown ```` 围栏里**，不要裸发 markdown。

- 裸发 markdown → 飞书渲染把长段挤成一坨，用户原话「一股脑把所有信息对在卡片消息上，很难看」
- 代码块 → 层级和断行原样显示
- 文档内含 `---` 分隔线时，外层用**四个反引号** ```` ```` ```` 包裹，防止内部围栏提前闭合
- 待确认词统一放文末一行 `⚠️ 专名待确认：…`，不要散落正文里
- 前后不要加解释、对比表格、过程复盘
- 禁止用 `MEDIA:` 发 .md —— 飞书会变成下载附件，用户看不到正文

### 文档必须包含以下三个部分，按顺序：

1. **YAML frontmatter**（必须，最先输出）
2. **正文**（一级标题 + 分段内容）
3. **来源**（末尾附上用户提供的原始转发文本；仅有本地 MP4 时注明未提供）

### YAML frontmatter 字段

```yaml
---
title: 文档标题，简洁准确
description: 一句话描述内容概要（25字内）
source: 用户提供的原始来源链接；没有则留空
tags: [标签1, 标签2]
created: YYYY-MM-DD
type: transcript
confidence: medium
speaker: 演讲者/作者（无@符号）
---
```

| 字段 | 必须 | 说明 |
|------|------|------|
| `title` | ✅ | 文档标题，简洁准确 |
| `description` | ✅ | 一句话描述内容概要（25字内）；**调用方（Agent）负责概括，不得依赖自动取正文前25字** |
| `source` | 视情况 | 用户提供的来源链接；没有时留空并说明，不编造 |
| `tags` | ✅ | 相关标签数组 |
| `created` | ✅ | 创建日期（YYYY-MM-DD） |
| `type` | ✅ | 类型（固定为 transcript） |
| `confidence` | ✅ | 转写可信度（high/medium/low）；未经逐段核对不要填 high |
| `speaker` | 视情况 | 演讲者/作者，**不带@符号** |

### 标题
有原始分享文案时取其首行（去除话题标签后）；没有时使用文件名或已核实的标题，不编造。

### 分段结构
用**一、二、三…** 编号，每段加**一级标题**（`# 一、[小标题]`）。

### 小标题标准

**Bad（不符合）**
- 超过15字
- 包含个人评论或情绪（"这个观点很牛"）
- 使用问句（"为什么要做品牌？"）
- 过于笼统（"一些思考"）

**Good（符合）**
- 动宾短语，≤15字
- 客观描述该段核心内容
- 示例："赛道无大小"、"性价比新公式"、"五万块如何做品牌"

### 分段合并原则
当连续两段主题相近且各自不足3句时，**合并为一段**。

### 正文规则
- **不擅自改动转写文本**。ASR 不等于准确原文；需要修正时以音频或其他可核对证据为准，记录不确定词。
- 专有名词经核实后才以正确写法呈现；无法核实则保留并标注待确认。
- 分段之间空一行，段内必要时换行但不过多

### 原始转发文本
如用户提供原始转发文本，文档末尾完整附上，含原链接。若只有本地 MP4，注明"原始转发文本未提供"，不可杜撰链接。

---

### 中间产物（不写入 Vault，仅本地保留）

| 文件 | 用途 |
|------|------|
| `transcript_raw.md` | 未经专有名词校正的原始转写；Agent 用来核对校正效果，不直接展示给用户 |
| `audio.wav` | 16kHz 单声道中间音频；转写成功后默认删除，`--keep-audio` 保留 |
| `whisper_out/` | Whisper 原始 JSON 分段输出；本地 Whisper 降级路径的原始产物 |
| `frames/` | 专有名词疑词截帧；仅在 `--frames` 参数触发时生成 |

所有产物统一存在 `<video_id>/` 目录下，不污染 `current/` 等共享路径。

## 疑词处理决策树

```
扫描文字，发现疑词
    │
    ├── 音频或画面文字可核实 → 校正并记录依据
    │
    ├── 有截帧支撑 → 校正后注明「✅ 截帧验证：xxx→xxx」
    │
    └── 无法判断 → 保留原文，注明「⚠️ 疑似听错，待确认」
```

| 情形 | 处理方式 |
|------|---------|
| 仅凭上下文推测 | 保留疑词并标注待确认，不静默修改 |
| 有截帧支撑 | 校正后注明「✅ 截帧验证：xxx→xxx」 |
| 无法判断 | 保留原文，注明「⚠️ 疑似听错，待确认」 |

## 输出前自检（每次必须）

每条内容发给用户之前，逐项检查：

- [ ] **YAML frontmatter 完整**
  - title ✅ description ✅ tags ✅ created ✅ type ✅ confidence ✅；source 有来源时填写
- [ ] **已包在 ```markdown 围栏里**（文档含 `---` 则用四反引号）
- [ ] **正文前后无多余解释/表格**，待确认词集中在文末 `⚠️` 一行
- [ ] **主标题是一级标题**（`# [标题]`）
- [ ] **每个分段是一级标题**（`# 一、[小标题]`）
- [ ] **所有正文改动均有音频或其他可核对依据；疑词已标注**
- [ ] **Step 2（扫词验证）已执行**，无遗漏疑词
- [ ] **用户提供的原始转发文本完整附在文档末尾；未提供时明确说明**
- [ ] **没有跳步骤**，没有自己想当然输出额外内容

**全部勾完才发。不确定的项目先问用户。**
