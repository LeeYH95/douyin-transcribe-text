## 格式规范

> 笔记属性（frontmatter）的**字段清单与必填/视情况划分**以 README《笔记属性规范》一节为准。
> 本文件只讲**交付形态**：怎么排版、怎么发、分段怎么切、交付前查什么。

### 发送方式

**发给用户时，整份文档必须包在 ```` ```markdown ```` 围栏里**，不要裸发 markdown。

- 裸发 markdown → 飞书渲染把长段挤成一坨，口头反馈「一股脑把所有信息对在卡片消息上，很难看」
- 代码块 → 层级和断行原样显示
- 文档内含 `---` 分隔线时，外层用**四个反引号** ```` ```` ```` 包裹，防止内部围栏提前闭合
- 待确认词统一放文末一行 `⚠️ 专名待确认：…`，不要散落正文里
- 前后不要加解释、对比表格、过程复盘
- 禁止用 `MEDIA:` 发 .md —— 飞书会变成下载附件，用户看不到正文
- 禁止用 `MEDIA:` 发 .mp4 —— 会被飞书拒收，见 `references/feishu-file-delivery.md`

### 文档必须包含以下三个部分，按顺序：

1. **YAML frontmatter**（必须，最先输出）
2. **正文**（一级标题 + 分段内容）
3. **来源**（末尾附上用户提供的原始转发文本；仅有本地 MP4 时注明未提供）

### YAML frontmatter 字段

字段清单、必填/视情况划分以 README《笔记属性规范》一节为准（唯一权威处）。
本 skill 特有的取值约定：

| 字段 | 取值约定 |
|------|------|
| `description` | **由 Agent 概括，不得依赖自动取正文前25字** |
| `source` | 抖音链接场景填原链接；本地 MP4 无原始链接时填本地文件路径（可追溯），**不得编造链接** |
| `type` | 本 skill 的口播逐字稿用 `transcript` |
| `confidence` | high/medium/low；**未经逐段核对不要填 high** |

**视情况字段**（`speaker` / `organization` / `event` / `authors`）无值时**直接省略整行**，
不写空字段占位。

> `scripts/transcribe.py` 的 `format_output()` 生成的只是**草稿**：`description` 和
> `source` 为空时它整行省略（并在 stderr 提醒）。交付前必须按 README《笔记属性规范》补齐 ——
> `scripts/quality_gate.py` 会把缺必填字段判为**阻断项**。

### 标题

有原始分享文案时取其首行（去除话题标签后）；没有时使用文件名或已核实的标题，不编造。

### 分段结构

用**一、二、三…** 编号，每段加**一级标题**（`# 一、[小标题]`）。

### 小标题标准

**Bad（不符合）**

- 超过15字
- 包含个人评论或情绪（"这个观点很牛"）
- 使用问句（"为什么要做品牌？"）
- 过于笼统（"一些思考"）

**Good（符合）**

- 动宾短语，≤15字
- 客观描述该段核心内容
- 示例："赛道无大小"、"性价比新公式"、"五万块如何做品牌"

### 分段合并原则

当连续两段主题相近且各自不足3句时，**合并为一段**。

### 正文规则

- **不擅自改动转写文本**。ASR 不等于准确原文；需要修正时以音频或其他可核对证据为准，记录不确定词。
- 专有名词经核实后才以正确写法呈现；无法核实则保留并标注待确认。
- 分段之间空一行，段内必要时换行但不过多

### 原始转发文本

如用户提供原始转发文本，文档末尾完整附上，含原链接。若只有本地 MP4，注明"原始转发文本未提供"，不可杜撰链接。

---

### 中间产物（不写入 Vault，仅本地保留）

| 文件 | 用途 |
|------|------|
| `transcript_raw.md` | 未经专有名词校正的原始转写；Agent 用来核对校正效果，不直接展示给用户 |
| `audio.wav` | 16kHz 单声道中间音频；转写成功后默认删除，`--keep-audio` 保留 |
| `whisper_out/` | Whisper 原始 JSON 分段输出；本地 Whisper 降级路径的原始产物 |
| `frames/` | 专有名词疑词截帧；仅在 `--frames` 参数触发时生成 |

所有产物统一在**本次下载的目录**里（目录名规则见 README《媒体落盘位置》——
`<主题>_<作者>_<日期>`），不污染 `current/` 等共享路径。

## 完整输出模板

```
---
title: [标题]
description: [一句话描述，≤25字]
source: [原始来源链接；本地 MP4 则填本地路径]
tags: [标签1, 标签2]
created: YYYY-MM-DD
type: transcript
confidence: medium
speaker: [演讲者]
---

# [标题]

# 一、[小标题]
[该段原文]

# 二、[小标题]
[该段原文]

# 三、[小标题]
[该段原文]

...

---

来源：[原始转发文本完整内容；没有则写"原始转发文本未提供"]
```

**注意：`transcript.md` 正文是连续段落，没有时间戳分节标题**（`## [HH:MM:SS]` 格式不存在）。时间轴信息只用于内部抽帧定位，不出现在最终文档里。

## 疑词处理决策表

| 情形 | 处理方式 |
|------|---------|
| 仅凭上下文推测 | 保留疑词并标注待确认，不静默修改 |
| 有截帧支撑 | 校正后注明「✅ 截帧验证：xxx→xxx」 |
| 音频或画面文字可核实 | 校正并记录依据 |
| 无法判断 | 保留原文，注明「⚠️ 疑似听错，待确认」 |

## 写入 Vault 前的硬闸（2026-10-01 明确要求）

**存在未核实词汇时，禁止写入 Vault。** 必须先向用户逐条确认，用户确认后才可写入。

| 情形 | 处理 |
|---|---|
| 截帧已核实 | 校正，交付时列明「帧证据表」 |
| 截帧**无法**核实（读数矛盾 / 帧未落到 / 多帧冲突） | **停下来问用户**，逐条列出候选和冲突证据，等回复 |
| 用户未回复 | 不写 Vault |

**同时禁止**：`⚠️ 专名待确认` 这类标注**不得写进 Vault 正文**——它本身就是对原文的改动，且未核实状态不应沉淀入库。标注只存在于交付给用户的对话中。

同一原则适用于幻觉重复标注（`〔⚠️ 疑似 ASR 幻觉重复 N 次，待确认〕`）——
写入 Vault 前去掉标注，只留核对过的原文。

## 无口播视频（纯 BGM）：不要硬凑逐字稿

SenseVoice 对**没有人声**的音频仍会吐出幻觉碎片（如「Yeah.🎼失实的。」）。
这类输出不是口播稿，交付出去等于给了一份假稿。

`transcribe.py` 的结果 JSON 带 `no_speech` 字段（有效字符/秒 < 1.5 判为真；
实测真人说话 4.5–8.1 字/秒，纯 BGM 0.03–0.47）。

| no_speech | 处理 |
|---|---|
| `true` | **不交付逐字稿**。说明「本片无口播（纯 BGM/画面展示）」，只交视频；要画面信息就转成「画面实录/整理稿」，走 `quality_gate.py --type note` |
| `false` | 正常走逐字稿流程 |

短于 10s 的片段不判定（样本少，容易误报）。

## 输出前自检（每次必须）

每条内容发给用户之前，逐项检查：

- [ ] **YAML frontmatter 完整**
  - title ✅ description ✅ source ✅ tags ✅ created ✅ type ✅ confidence ✅
  - 视情况字段无值时整行省略
- [ ] **已包在 ```markdown 围栏里**（文档含 `---` 则用四反引号）
- [ ] **正文前后无多余解释/表格**，待确认词集中在文末 `⚠️` 一行
- [ ] **主标题是一级标题**（`# [标题]`）
- [ ] **每个分段是一级标题**（`# 一、[小标题]`）
- [ ] **所有正文改动均有音频或其他可核对依据；疑词已标注**
- [ ] **疑词截帧验证已执行**（`verify_terms.py`），输出「已核实 / 仍未核实」两张表
- [ ] **幻觉重复检测与质量闸已跑**（见 `delivery-gate.md`），无阻断项
- [ ] **用户提供的原始转发文本完整附在文档末尾；未提供时明确说明**
- [ ] **没有跳步骤**，没有自己想当然输出额外内容

**全部勾完才发。不确定的项目先问用户。**
