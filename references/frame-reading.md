# 从视频帧里读文字：通用规矩

> **读这里的条件**：需要从视频帧里读出文字 —— 疑词核实、提示词提取、幻灯片/UI 文字都算。
> 疑词核实的**流程**见 `frame-verification.md`；本文件只讲所有读帧任务共通的纪律，
> 读一次就够，不要在每个分支里重抄一遍。

---

## ⚠️ 前置条件：会话模型必须能读图

| 情形 | 处理方式 |
|------|---------|
| 会话模型能读图 | 正常读帧 |
| 会话模型不能读图 | **暂停**，告知用户：①换支持视觉的模型会话继续；②在当前会话中自行读帧截图、告诉我看到什么，我再判断 |

禁止在 VLM 不可用时跳过读图、凭猜测输出结果。

---

## 必须串行，禁止并发

并发跑视觉识别会**静默返回空结果**（不报错，看着像「图里没字」）。
一次传多张给同一个程序即可 —— 内部逐张处理。

---

## 只问「抄录」，绝不问「画面里有什么」

VLM 实测会**编造画面里没有的内容**：对 215s 帧提问「画面里有什么」，
VLM 返回了一整篇《教父》电影分析 —— 画面里根本没有。它把提示词里的 `a16z`
当成了线索硬凑。

必须用严格 OCR 提示：

```
只逐字抄录底部黑色字幕条的文字，不要描述画面，不要补充画面以外的内容。
```

---

## 读哪一块：整帧 vs 字幕条

| 目标 | 用哪张 |
|------|--------|
| 核实口播疑词（烧录字幕） | 字幕条（底部裁剪） |
| 读画面里的**提示词 / 海报文字 / 幻灯片 / UI** | **整帧** —— 字幕条会把内容裁掉 |
| 屏幕录制类视频（横屏） | 整帧优先 —— UI 文字是最强证据源 |

字幕条由 `verify_terms.py` 产出（全帧 + 底部字幕条各一张）；手动抽帧只有整帧。

---

## 密集中文 → 本地 Vision OCR

内置多模态读图对**密集中文**经常读不准或读不出。本地 Vision 稳定，
且不依赖会话模型是否支持视觉。

```bash
swiftc -O "<douyin-transcribe-text-skill-dir>/scripts/ocr_vision.swift" -o /tmp/ocr_vision
/tmp/ocr_vision <frame_*.jpg>     # 一次传多张，程序内部逐张处理
```

---

## 帧必须先拷进工作区

`view_image` 只认工作区目录下的文件。从外接 SSD 抽的帧需先拷到工作区：

```bash
mkdir -p ~/.openclaw/workspaces/knowledge-master/verify_frames
cp "<媒体根目录>/抖音/<主题>_<作者>_<日期>/frames/"*.jpg \
   ~/.openclaw/workspaces/knowledge-master/verify_frames/
```

目录名规则见 README《媒体落盘位置》—— `<主题>_<作者>_<日期>`，不是 video_id。
